# Concepts

Tenant safety means payment and invoice queries carry the organization id, even when the caller supplied a globally unique identifier. The global provider-event lookup instead verifies the returned event organization and payload before acknowledging a replay. Authorization means role permission is checked before work. Idempotency means the provider event id and normalized payload identify one meaning. Atomicity means event claim, payment/invoice state, audit, and outbox commit together. These concepts answer different questions and should not be collapsed into one “secure webhook” label.

The mock provider has two transitions. A success moves a payment to succeeded and an open invoice to paid. A failure moves a payment to failed with optional details. Once succeeded, a later failure is ignored and audited. A successful retry clears old failure fields. A *second success* with a new provider event id is not a no-op: the payment and invoice updates are skipped (`payments.service.ts:85`), but the audit row and a fresh `payment.succeeded` outbox row are still written (`:103-116`), which matters because worker-created payments are usually already `succeeded` (finding F2 in chapter 06). A duplicate processed event is acknowledged without rereading or writing business state.

Exercise: explain why an event must not be created before payment lookup. (answer: [06, chapter 02](06-SOLUTIONS-AND-REVIEW.md#chapter-02-exercise))

Typed errors make the contract useful to clients. A 400 can be corrected, a 403 needs access, a 404 identifies a missing scoped target, and a 409 can be retried or investigated. Unknown errors become sanitized 500 responses. Keep these concepts separate during review: tenant filtering does not replace permission checks, and a mock replay test does not prove provider delivery semantics.

A useful habit is to name the invariant before coding. For example: no denied or missing target creates an event; one accepted event creates at most one outbox intent; success is never regressed by failure. Each invariant maps to a focused fixture and negative assertion.

For the shared error contract, DomainError belongs to the domain package and has no dependency on Express. `errorMiddleware` maps its validation, forbidden and conflict categories to HTTP 400, 403 and 409 (`apps/api/src/shared/errors.ts:21-24`). This keeps expected billing failures distinguishable from unknown infrastructure failures. Note what is *not* mapped: Prisma's `findFirstOrThrow` not-found error (P2025) falls through to the sanitized 500, so routes that use it, such as `POST /api/billing/invoices/:invoiceId/pay`, answer 500 for a foreign or missing id instead of 404 (finding F5).

## The tenant header is an input the attacker controls

Every request in this API resolves its tenant from `x-org-slug` and `x-user-email` (`apps/api/src/shared/auth.ts:15-16`), and both headers have defaults: `"acme"` and `DEFAULT_USER_EMAIL`, which defaults to `owner@acme.test` (`apps/api/src/config.ts:6`), the user the seed makes an `owner`. A request with no headers at all is therefore the Acme owner (finding F1). Header tenancy is tolerable only for a local demo driven by an operator. It is *not* fine for a webhook. A payment provider posting to `/webhooks/mock` cannot present those headers, and anyone who can reach the endpoint can present any of them. So the tenant scoping the service performs (`payment.findFirst({ where: { id, organizationId: tenant.organizationId } })`) is only as trustworthy as the header. In production the organization must come from something the caller cannot forge: a provider signature over the body verified with the tenant's webhook secret (which identifies the tenant), or the stored `providerEventId` written when the payment was created. The mock route carries this caveat as a comment (`payments.routes.ts:25-28`). Predict: with header-derived tenancy, what does a forged `x-org-slug` for another tenant plus a guessed `paymentId` achieve? (It marks another tenant's invoice paid: the scoping check passes because the attacker chose the scope.)
